       No .itcm_text section in golden.ld or firmware.map.
       There is nothing to overflow.
     If this fires → BUG in rules/itcm_overflow.py (chip-agnostic assumption)

[A4] unaligned_dma_buffer  (INFO)
     Why it must NOT fire:
       g_rx_dma_buf and g_tx_dma_buf both use __attribute__((aligned(32))).
       .map confirms: __dma_buffers_start = 0x20000040
       0x20000040 % 32 = 0  → perfectly aligned.

[A5] dma_buffer_in_non_dma_region  (ERROR)
     Why it must NOT fire:
       DMA buffers are in .dma_buffers section → SRAM1 (0x20000000).

       CCM is dma_accessible: false — but NO DMA buffer is in CCM.
       Stack is in CCM, which is correct and expected.
     If this fires → BUG in region_classifier.py (misidentifying stack as DMA buf)

[A6] dma_bus_contention  (WARNING/HEURISTIC)
     Why it must NOT fire:

       share the same bus port. Here:
         DMA buffers: SRAM1 (AHB_S0) — correct, DMA-accessible
         Stack: CCM (CCM_ONLY bus) — isolated from AHB entirely
       There is NO CPU+DMA contention on the stack region.
       The rule should only fire on F407 when DMA and CPU-heavy code
       share SRAM1 exclusively with no CCM isolation. That is not the case here.
     If this fires → BUG in bus_contention heuristic (over-triggering)

[A7] isr_calls_blocking_function  (WARNING)
     Why it must NOT fire:
       DMA2_Stream0_IRQHandler: writes a register, sets flag, returns.
       TIM2_IRQHandler: clears flag, increments counter, returns.
       USART1_IRQHandler: reads SR, clears flag, returns.
       None call uart_tx_byte, HAL_Delay, or any blocking function.
     If this fires → BUG in blocklist matching (false positive)

[A8] recursion_detected  (CRITICAL)

         main → {system_init, uart_init, main_loop}
