[A1] MUST NOT fire: isr_in_flash  (Rule 1 WARNING)
  Why: TIM2_IRQHandler (0x00000000), DMA2_Stream0_IRQHandler (0x0000003C),
       SPI1_IRQHandler (0x00000090) are all in ITCM range.
       Rule 1 fires ONLY when ISR address ∈ [0x08000000, 0x08100000).
       These addresses are in [0x00000000, 0x00004000) = ITCM.
  If this fires → BUG: address range check fails to distinguish ITCM from flash.

[A2] MUST NOT fire: itcm_overflow  (Rule 3 WARNING/CRITICAL)
  Why: .itcm_text = 700 bytes / 16,384 bytes = 4.3%. Far below any threshold.
  If this fires → BUG: section size extraction error or wrong ITCM capacity.

[A3] MUST NOT fire: unaligned_dma_buffer  (Rule 5 INFO)
  Why: uart_tx_dma_buf at 0x2004C000 → 0x2004C000 % 32 = 0 ✓
       adc_dma_buf at 0x2004C100     → 0x2004C100 % 32 = 0 ✓
       spi_rx_buf at 0x20010000      → 0x20010000 % 32 = 0 ✓
       All three DMA buffers are 32-byte aligned.
  If this fires → BUG: alignment arithmetic error.

[A4] MUST NOT fire: stack_overflow_risk  (Rule 4 CRITICAL)
  Why: Worst-case chain = main(16) + control_loop(24) + pid_update(40) = 80B
       Budget = 2048B. Usage = 3.9%.
  If this fires → BUG: stack threshold applied incorrectly.

[A5] MUST NOT fire: dma_buffer_in_non_dma_region  (ERROR)
  Why: uart_tx_dma_buf and adc_dma_buf are in SRAM2 (dma_accessible: true).
       spi_rx_buf is in SRAM1 (dma_accessible: true).
       No DMA buffer is in ITCM or DTCM (which are dma_accessible: false).
  If this fires → BUG: wrong region classification.

[A6] MUST NOT flag veneer stubs as ISRs or as misplaced functions
  Why: The linker emits __control_loop_veneer at 0x08000358 (flash).
       This is a linker-generated trampoline, not user code.
       Symbol name ends in '_veneer' — must be ignored by the rule engine.
       Flagging it as "function in flash that should be in ITCM" is wrong.
  If this fires → BUG: veneer symbols not filtered in region_classifier.py
